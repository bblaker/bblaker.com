The temptation with a project like this is to write the interesting part first and
measure later. That's how you end up with a number you can't reproduce and a graph
you don't trust.

So: the harness comes first. Two requirements, both boring.

**It has to be repeatable.** Same traffic profile, same duration, same warmup, run from
a script with no arguments. If I have to remember flags, I'll run it differently in
three weeks and compare two things that aren't comparable.

**It has to run on hardware I already own.** A benchmark that needs a lab I don't have
is a benchmark I'll do twice and then stop doing.

## What I'm recording

Requests per second is the least interesting number here and the one everyone quotes.
What I actually want is the tail — p99 and p99.9 under a *fixed* arrival rate, which is
why the harness uses `wrk2` rather than `wrk`. Coordinated omission makes the difference
between a latency graph and a latency fantasy.
